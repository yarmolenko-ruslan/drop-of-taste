# Структура сервера

Сервер организован по функциональным модулям (feature-based modular monolith):
код одной предметной области и его тесты находятся рядом. Все модули работают
в одном процессе Fastify и используют существующую MongoDB.

```text
server/
├── index.ts                 # запуск, зависимости, регистрация маршрутов, остановка
├── app.ts                   # создание Fastify, общие HTTP hooks, маршруты авторизации
├── http/
│   ├── origins.ts           # общая проверка Origin
│   └── origins.test.ts
├── modules/
│   ├── admin/
│   │   ├── routes.ts        # административное API и загрузка изображений
│   │   ├── credentials.ts   # пароль владельца
│   │   ├── access.ts        # сессии, права, сотрудники и смена паролей
│   │   ├── activity.ts      # полный журнал административных действий
│   │   ├── response-access.ts # ответы с учётом прав
│   │   └── *.test.ts
│   ├── auth/
│   │   ├── service.ts       # подтверждение звонка пользователя и сессии
│   │   ├── types.ts
│   │   ├── limits.ts
│   │   ├── session-cookie.ts
│   │   ├── memory-store.ts
│   │   ├── mongo-store.ts
│   │   └── *.test.ts
│   ├── catalog/
│   │   ├── mongo-catalog.ts # хранение, кеш и начальное заполнение каталога
│   │   ├── template.ts
│   │   └── *.test.ts
│   ├── content/
│   │   ├── service.ts       # чтение и подготовка содержимого сайта
│   │   ├── updates.ts       # уведомления об обновлениях через SSE
│   │   └── *.test.ts
│   ├── orders/

│   │   ├── checkout.ts      # проверка корзины и расчёт стоимости
```

## Куда добавлять код

- Новое поведение существующей области — в соответствующий каталог `modules/`.
  Небольшой модуль не требует отдельных слоёв controllers/services/repositories.
- Новая внешняя интеграция — в `integrations/`; платёжный клиент остаётся
  рядом с ограничителями запросов в `modules/payments/`.
- Общие серверные HTTP-проверки — в `http/`. Доменная логика остаётся
  в своём модуле, даже если её использует другой модуль.
- Локальный тест — рядом с проверяемым кодом. Сценарий нескольких модулей —
  в `tests/integration/`, общая проверка безопасности — в `tests/security/`.
- Общие клиенту и серверу контракты и схемы — в корневой `shared/`.
  Клиент не импортирует `server/`. Шаблон каталога пока использует существующие
  начальные данные из `src/features/catalog/model/`.

Импорты указывают на конкретные файлы. Сборка зависимостей и запуск остаются
в `index.ts`; файл не импортируется из модулей или тестов. Пути `public/uploads`
и `data/mongodb` по-прежнему отсчитываются от корня проекта. Команды запуска
не изменились: `npm run dev:api` и `npm run start:api`.

## Проверки

Из корня проекта:

```bash
npm run typecheck
npm run lint
npm test
npm run build
npm run test:stress
```

Только серверные тесты: `npm test -- server`. Vitest находит `*.test.ts`
рекурсивно во всех каталогах сервера. Интеграционные тесты и нагрузочный
сценарий используют временные MongoDB и требуют локальных соединений;
рабочая база и настоящие внешние провайдеры в них не используются.

Журналы `admin_activity`, `admin_audit` и `payment_events` хранятся 90 дней: индекс MongoDB TTL по `at` удаляет старые документы автоматически. API также исключает записи старше 90 дней, не дожидаясь очередного прохода TTL. История заказов и платёжное состояние заказа сохраняются. Чтение данных, автообновления списков и навигация журнал не пополняют; изменение данных, вход/выход и операции с временными реквизитами записываются.
