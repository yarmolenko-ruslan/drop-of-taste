# drop-of-taste

Адаптивный сайт (этап 1) с последующей упаковкой в Android/iOS (этап 2). Правила разработки — [CLAUDE.md](CLAUDE.md), журнал решений — [CHANGES.md](CHANGES.md).

## Стек

Vite 8 · React 19 · TypeScript (strict) · React Router 7 · Zustand 5 · CSS Modules + CSS custom properties · Vitest + React Testing Library · ESLint 9 · Prettier.

## Запуск

Требуется Node.js 24+ и npm (единственный package manager проекта).

```bash
npm install
npm run dev
```

## Команды

| Команда             | Назначение                                  |
| ------------------- | ------------------------------------------- |
| `npm run dev`       | Dev-сервер Vite                             |
| `npm run dev:db`    | Постоянная локальная MongoDB на порту 27017 |
| `npm run dev:api`   | Локальный API на порту 3001                 |
| `npm run start:api` | Запуск локального API без наблюдения файлов |
| `npm run build`     | Проверка типов и production-сборка в `dist` |
| `npm run preview`   | Локальный просмотр production-сборки        |
| `npm run lint`      | ESLint                                      |
| `npm run typecheck` | Проверка типов TypeScript                   |
| `npm test`          | Unit/компонентные тесты (Vitest)            |
| `npm run format`    | Форматирование Prettier                     |

Для полного локального запуска откройте три терминала в папке проекта:

```bash
npm run dev:db
npm run dev:api
npm run dev
```

Затем откройте `http://localhost:5173`. База из `dev:db` хранит данные в `data/mongodb` и сохраняет их после остановки и повторного запуска. При наличии своей MongoDB задайте `MONGODB_URI` в `.env`. Для входа заполните серверный `SMS_RU_API_ID`: пользователь звонит со своего телефона на номер, который покажет сайт. Вход подтверждается автоматически, без ввода кода. Меню, профиль, адреса, сессии и тестовые заказы хранятся в MongoDB. Production-запуск остаётся заблокированным до настройки HTTPS, cookie и инфраструктуры. Настройка звонков описана ниже.

## Авторизация SMS.ru

Вход работает по [документации SMS.ru](https://sms.ru/api/call): **пользователь сам звонит** со своего телефона на номер, показанный сайтом. Ввода кода нет. В `.env` заполните серверный `SMS_RU_API_ID`, затем перезапустите `npm run dev:api`. Не используйте префикс `VITE_`: ключ не должен попадать в браузер. Без ключа сервер сообщает об отсутствующей настройке и не включает заглушку.

`POST /api/auth/call/start` принимает российский мобильный номер и согласие на обработку данных. Сервер резервирует лимиты в MongoDB, один раз вызывает `POST https://sms.ru/callcheck/add` и сохраняет `check_id`. Браузер получает номер для звонка, время окончания проверки и случайный токен попытки. Идентификатор провайдера остаётся на сервере; в базе хранится только SHA-256 токена попытки.

Обработчик приводит номер провайдера к виду `+7…`: поддерживает строку и целое число, начальную `8`, пробелы, скобки и дефисы. Основное поле — `call_phone`; также поддерживается `call_number` из PHP-примера документации. Если оба поля присутствуют, они должны указывать один номер. HTML из ответа не используется. Отсутствующий, недопустимый или противоречивый номер отклоняется без автоматической новой регистрации; причина и тип поля фиксируются в диагностике без полного номера.

На звонок отведено пять минут с начала запроса. Модалка показывает номер и ссылку `tel:`, затем раз в три секунды проверяет подтверждение через `POST /api/auth/call/status`. При скрытой вкладке опрос приостанавливается и возобновляется при возвращении. Сервер ограничивает обращения к `callcheck/status` одной проверкой на попытку за три секунды даже при параллельных запросах к разным экземплярам API. Только `status=OK`, `status_code=100`, `check_status=401` разрешают создать сессию. Состояния 400 (ожидание), 402 (истечение), сетевые ошибки и флаги из браузера не авторизуют пользователя.

После нажатия «Продолжить» номер фиксируется, в том числе при ошибке запроса. Поменять его можно, закрыв модалку и открыв заново. Поля кода и кнопок смены номера нет. Истёкшую или неудачную проверку пользователь запускает заново вручную для того же номера; автоматической регистрации новой попытки нет.

Сохраняются пауза 60 секунд между регистрациями, до пяти попыток на номер за скользящие 24 часа, 20 в час на IP и 200 за 24 часа на весь сервис. Успешная авторизация, закрытие окна и перезапуск сервера не сбрасывают ограничения. Подтверждённый отказ провайдера освобождает резерв; при таймауте, повреждённом ответе или неизвестном результате лимит остаётся, поскольку регистрация могла состояться. Вызов провайдера выполняется вне повторяемых транзакций MongoDB. Проверка статуса не создаёт новую заявку и не вызывает исходящий звонок или SMS.

Локально необязательный `ip` в SMS.ru не передаётся. На публичном сервере нужен реальный IP пользователя от конкретного доверенного reverse proxy: по нему SMS.ru выбирает доступный для звонка номер. Сейчас произвольным `X-Forwarded-For` сервер не доверяет. Webhook можно добавить при настройке публичного HTTPS; локальная версия использует опрос статуса.

Для диагностики сервер пишет `sms_ru_callcheck` в терминал и `auth_call_events` на семь дней: операция start/status, время, маскированный телефон, результат, HTTP-статус, код SMS.ru, `check_id` и стоимость, если она указана в ответе. API-ключ, полный телефон, токен попытки/сессии и произвольный ответ не журналируются. Сбой журнала не повторяет запрос провайдера.

## Панель администратора

Откройте `http://localhost:5173/admin`. Пароль хранится в локальном `.env` как `ADMIN_PASSWORD`; если его нет, API печатает временный пароль при запуске. История заказов клиента загружается страницами по 50 записей кнопкой «Показать ещё заказы». В разделе «Сайт и баннеры» также доступны тариф доставки, видимость блоков главной, основные цвета, подписи ссылок и кнопок, описание страницы и значок вкладки. Новые баннеры поддерживают редактируемый текст поверх фотографии и изменение порядка. Возможности и результаты проверки описаны в [проверке админ-панели](ADMIN-PANEL-2026-11-15.md). Панель позволяет менять контакты, тексты и фотографии основных страниц, логотип, баннеры, акции, бонус-коды, юридические страницы, разделы меню, карточки и цены. Картинки можно загрузить с компьютера (до 5 МБ) или указать ссылку HTTPS. Контент и меню обновляются после сохранения в панели, восстановления связи и возвращения к странице. Открытая вкладка дополнительно проверяет меню раз в минуту; контент перечитывается не реже раза в минуту и в момент запуска или завершения акции. Файлы загружаются в `public/uploads`, а тексты и меню — в MongoDB. Изменения в текстах и меню сохраняются в локальной базе после перезапуска `dev:db`.

Для импорта из iiko нужны учётные данные приложения и внешний каталог кафе. Заполните `IIKO_*` в `.env` по примеру `.env.example`, перезапустите API и откройте вкладку iiko в панели. Кнопка импортирует только простые блюда с одной ценой: составные наборы, варианты размеров, обязательные модификаторы и реальные заказы требуют отдельной интеграции. Тексты и фотографии карточек, изменённые вручную, импорт не перезаписывает; цену и доступность импортированных карточек обновляет. Подробности — в [серверной документации](docs/backend.md).

## Тестовая оплата ЮKassa

Добавьте в локальный `.env` `YOOKASSA_TEST_SHOP_ID=1522340` и `YOOKASSA_TEST_SECRET_KEY=` с ключом тестового магазина из кабинета ЮKassa. Файл `.env` исключён из Git; ключ нельзя помещать в клиентский код. Перезапустите `dev:api`, затем откройте сайт, войдите, позвонив на показанный сайтом номер, добавьте блюдо в корзину и выберите «Перейти к тестовой оплате». ЮKassa перенаправит обратно на страницу результата, которая проверит статус платежа через сервер. Для успешной проверки используйте тестовую карту `5555 5555 5555 4444`, будущую дату и любой CVC. Настоящие деньги не списываются. После оплаты заказ остаётся тестовым и не поступает в кафе.

Пока сайт работает только локально, уведомления ЮKassa не настраиваются: статус проверяется после возврата покупателя и автоматически в открытом личном кабинете. Для публичного запуска потребуется HTTPS-адрес уведомлений и отдельная настройка чеков.

## Проверка нагрузки и безопасности

`npm run test:stress` поднимает изолированную временную MongoDB и HTTP API, проверяет основные серверные сценарии и выполняет 12 300 запросов с нагрузкой до 200 одновременных клиентов. Команда не читает `.env` и не использует рабочие данные, настоящие SMS, платежи или iiko. В выводе — задержки, скорость и память после сборки мусора. Для запуска нужны разрешённые локальные соединения. Метрики этого локального прогона не являются оценкой production-сервера.

В нагрузочном процессе внешний `fetch` заблокирован: разрешён только точный адрес созданного тестового API, переходы по HTTP-редиректам запрещены. Любая попытка вызвать SMS.ru, платёжный сервис или другой локальный API приводит к ошибке до сетевого обращения. Отчёт содержит количество заблокированных попыток и имитированных регистраций проверки. Проверка ограничителя: `npm test -- scripts/stress-network.test.ts`.

Защита расходов проверяется командой `npm test -- server/modules/auth/spend-protection.test.ts`. Используются искусственный ключ и имитация SMS.ru без делегирования запросов в сеть. Сценарии: 1500 повторных/некорректных запросов и проверок статуса звонка; по 1000 попыток при таймауте, внутренней ошибке и повреждённом ответе; сбои БД; 1302 попытки на трёх экземплярах сервиса с общей MongoDB, включая ограничения номера, IP, общего бюджета и переход через 24 часа. Реальный баланс SMS.ru эти тесты не используют.

Персональные кабинеты сотрудников доступны на `/staff`. Владелец входит на `/admin` прежним `ADMIN_PASSWORD` и создаёт сотрудников во вкладке «Сотрудники»: имя, уникальный логин, шаблон должности и чекбоксы «Просмотр»/«Редактирование» по каждому разделу. Оба сняты — нет доступа. Клиенты доступны только для просмотра. Сотрудники, журнал и iiko — только владельцу. Временный пароль выдаётся при создании/сбросе в отдельном окне, действует 48 часов и требует смены при первом входе; личный пароль — 12–128 символов. Данные можно повторно показать в текущей карточке до ухода со страницы. Изменение карточки/прав, блокировка и сброс/смена пароля отзывают сессии сотрудника. Физическое удаление сотрудников не предусмотрено, используется блокировка. Список ограничен 500 записями. Подробности: [ТЗ](ADMIN_ACCESS_SPEC.md), [отчёт безопасности и регрессий](ADMIN_ACCESS_SECURITY_REVIEW.md).

Обновление кабинетов: права выдаются чекбоксами «Просмотр» и «Редактирование». Временный пароль автоматически открывается в отдельном окне после создания/сброса; данные можно скопировать и повторно показать до ухода со страницы. Если пароль потерян: «Сотрудники» → выбрать сотрудника → «Пароль для входа» → «Выдать новый временный пароль». Журнал фиксирует действия обеих ролей с автором, временем и результатом, фильтрами и постраничной историей. Подробности — [в отчёте обновления](ADMIN_ACCESS_UI_AUDIT_UPDATE.md). Результаты последующей проверки гонок сессий, устаревших реквизитов, отказов журнала и регрессий — [в углублённом отчёте](ADMIN_ACCESS_DEEP_REVIEW.md).

Авторизация подтверждает звонок пользователя через SMS.ru; производственный запуск пока заблокирован до настройки инфраструктуры. Смена `ADMIN_PASSWORD` после перезапуска отзывает только сессии владельца; сессии сотрудников проверяются по их собственной версии доступа. Пароли интеграций остаются в конфигурации сервера.

## Архитектурные границы

`src/app → src/screens → src/features → src/shared`. Нижний слой не импортирует верхний — это проверяет ESLint (`no-restricted-imports`). `server/` — отдельная серверная граница, которую клиентские модули не импортируют. Каталоги создаются по мере появления кода.

Сервер организован по функциональным модулям: `server/modules/` содержит авторизацию, каталог, заказы, платежи, профиль, контент и админку; `server/integrations/` — интеграцию iiko; `server/http/` — общие HTTP-проверки. Локальные тесты лежат рядом с кодом, межмодульные сценарии и общие проверки безопасности — в `server/tests/`. Карта каталогов и правила добавления файлов — в [server/README.md](server/README.md).

Журналы админки содержат конкретные операции: создание и изменение данных, этапы заказов, вход и операции с паролями. Навигация, чтение списков, поиск и ввод в поля не записываются. Действия, изменения и события оплаты хранятся 90 дней, затем автоматически удаляются; сами заказы сохраняются. Записи сгруппированы по дням, неделям и месяцам по времени Красноярска. ## Открытые вопросы

- SEO: Vite отдаёт SPA без готового HTML. Если публичный каталог должен индексироваться поиском, это нужно решить до реализации каталога (см. CLAUDE.md, раздел 3.2).
- Хостинг SPA должен отдавать `index.html` на все вложенные маршруты.
