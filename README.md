# drop-of-taste

Адаптивный сайт (этап 1) с последующей упаковкой в Android/iOS (этап 2). Правила разработки — [CLAUDE.md](CLAUDE.md), журнал решений — [CHANGES.md](CHANGES.md).

## Стек

Vite 8 · React 19 · TypeScript (strict) · React Router 7 · Zustand 5 · CSS Modules + CSS custom properties · Vitest + React Testing Library · ESLint 9 · Prettier.

## Запуск

Требуется Node.js 24+ и npm (единственный package manager проекта).

```bash
npm install
npm run dev
```

## Команды

| Команда             | Назначение                                  |
| ------------------- | ------------------------------------------- |
| `npm run dev`       | Dev-сервер Vite                             |
| `npm run dev:db`    | Постоянная локальная MongoDB на порту 27017 |
| `npm run dev:api`   | Локальный API на порту 3001                 |
| `npm run start:api` | Запуск локального API без наблюдения файлов |
| `npm run build`     | Проверка типов и production-сборка в `dist` |
| `npm run preview`   | Локальный просмотр production-сборки        |
| `npm run lint`      | ESLint                                      |
| `npm run typecheck` | Проверка типов TypeScript                   |
| `npm test`          | Unit/компонентные тесты (Vitest)            |
| `npm run format`    | Форматирование Prettier                     |

Для полного локального запуска откройте три терминала в папке проекта:

```bash
npm run dev:db
npm run dev:api
npm run dev
```

Затем откройте `http://localhost:5173`. База из `dev:db` хранит данные в `data/mongodb` и сохраняет их после остановки и повторного запуска. Уже работающую временную базу нужно один раз остановить и запустить заново; её прежние данные не переносятся автоматически. При наличии своей MongoDB скопируйте `.env.example` в `.env` и задайте `MONGODB_URI`. Одноразовый код входа показывается над полем ввода в модальном окне на пять минут и также появляется в терминале `dev:api`; реальные SMS не отправляются. Меню, профиль, адреса, сессии и тестовые заказы хранятся в MongoDB. Production-запуск заблокирован до настройки настоящего SMS и инфраструктуры. Ожидаемое поведение и проверки описаны в [ТЗ](docs/spec-local-mvp.md), серверные решения — в [docs/backend.md](docs/backend.md).

## Панель администратора

Откройте `http://localhost:5173/admin`. Пароль хранится в локальном `.env` как `ADMIN_PASSWORD`; если его нет, API печатает временный пароль при запуске. Панель позволяет менять контакты, тексты и фотографии основных страниц, логотип, баннеры, акции, бонус-коды, юридические страницы, разделы меню, карточки и цены. Картинки можно загрузить с компьютера (до 5 МБ) или указать ссылку HTTPS. Контент сайта перечитывается не реже раза в минуту и в момент запуска или завершения акции; каталог обновляется после обновления страницы. Файлы загружаются в `public/uploads`, а тексты и меню — в MongoDB. Изменения в текстах и меню сохраняются в локальной базе после перезапуска `dev:db`.

Для импорта из iiko нужны учётные данные приложения и внешний каталог кафе. Заполните `IIKO_*` в `.env` по примеру `.env.example`, перезапустите API и откройте вкладку iiko в панели. Кнопка импортирует только простые блюда с одной ценой: составные наборы, варианты размеров, обязательные модификаторы и реальные заказы требуют отдельной интеграции. Тексты и фотографии карточек, изменённые вручную, импорт не перезаписывает; цену и доступность импортированных карточек обновляет. Подробности — в [серверной документации](docs/backend.md).

## Тестовая оплата ЮKassa

Добавьте в локальный `.env` `YOOKASSA_TEST_SHOP_ID=1522340` и `YOOKASSA_TEST_SECRET_KEY=` с ключом тестового магазина из кабинета ЮKassa. Файл `.env` исключён из Git; ключ нельзя помещать в клиентский код. Перезапустите `dev:api`, затем откройте сайт, войдите по локальному коду из окна входа, добавьте блюдо в корзину и выберите «Перейти к тестовой оплате». ЮKassa перенаправит обратно на страницу результата, которая проверит статус платежа через сервер. Для успешной проверки используйте тестовую карту `5555 5555 5555 4444`, будущую дату и любой CVC. Настоящие деньги не списываются. После оплаты заказ остаётся тестовым и не поступает в кафе.

Пока сайт работает только локально, уведомления ЮKassa не настраиваются: статус проверяется после возврата покупателя и по кнопке в личном кабинете. Для публичного запуска потребуется HTTPS-адрес уведомлений и отдельная настройка чеков.

## Архитектурные границы

`src/app → src/screens → src/features → src/shared`. Нижний слой не импортирует верхний — это проверяет ESLint (`no-restricted-imports`). `server/` — отдельная серверная граница, которую клиентские модули не импортируют. Каталоги создаются по мере появления кода.

## Открытые вопросы

- SEO: Vite отдаёт SPA без готового HTML. Если публичный каталог должен индексироваться поиском, это нужно решить до реализации каталога (см. CLAUDE.md, раздел 3.2).
- Хостинг SPA должен отдавать `index.html` на все вложенные маршруты.
